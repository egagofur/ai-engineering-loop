# Newcomer UX in a clean sandbox (C-47..C-56)

Source: end-to-end run of v2.12.0 (`main` at `2db97b1`, and the same version from npm) in throwaway `node:20-slim` containers with nothing else installed: no git config, no `gh`/`glab`, no agent host. The CLI was driven by hand, as far as it goes without an LLM (the Devil's Advocate output was a stand-in `{"findings":[]}` ledger). Rerun with `scripts/sandbox-e2e.sh` (see `bench/sandbox/README.md`); every issue below has a `UX` probe id in `bench/sandbox/scenario.sh` that flips from OPEN to FIXED when the fix lands.

Headline: the gated engine holds up. Goal, Maker, verify, review, judge and deliver all worked in order, the refusals were right (deliver without `--approve`, verify before the Maker gate, RUN_CONFLICT on a second task), and npm, Node 18 and Node 20 installs all worked. Newcomers get stuck **around** the engine: missing prerequisites are found late and reported as raw errors, nothing tells them to install the agent skill, and the CLI-only path has gaps (no Goal template).

## What AEL needs installed

| Tool | Need | What breaks without it |
|---|---|---|
| Node.js >= 18 | **Required** | Node 16 installs with an npm `EBADENGINE` warning, and `init` works with no warning. Only `doctor` says NOT READY. |
| npm (comes with Node) | **Required** | Needed for `npm i -g` / `npx`. |
| git, in a repo with at least one commit | **Required** | `gate maker --from-git`, the impact map, baseline binding, receipts and `run --worktree` all need it. Without git: `spawnSync git ENOENT`. Folder not a repo: about 100 lines of `git diff` usage text. No commit yet: `bad revision 'HEAD'`. Every check before `gate maker` passes first (`init`, `status`, `doctor`, `run`, `goal freeze`), so the user finds out at Stage 4. |
| git `user.name` / `user.email` | **Required to deliver** | AEL never commits, but Stage 8 commits before `deliver`. Without them the commit fails. Nothing in AEL warns. |
| An agent host with the `ael` skill (Claude Code, Codex, Cursor, ...) | **Required for the intended flow** | Without a host the CLI can drive every gate, but the Maker, Devil's Advocate and Judge are model work, so the loop is manual. Installing the skill is a separate step (`setup` / `sync-hosts`) that the Get Started section never mentions. |
| `gh` (logged in) | Optional (GitHub remotes) | `doctor` and `deliver` warn (`adapter-auth`). The GitHub adapter falls back to the standard adapter and prints a compare URL. |
| `glab` (logged in) | Optional (GitLab remotes) | Same as `gh`, for the gitlab adapter. |
| curl, Python, Docker, a browser | Not needed | A browser is only for `ael studio`. |

## C-47 · P1 · Deliver refuses a change that is not committed

**Now:** `gate delivery` checks secrets, debug markers, templates and stray files. It does not check that `HEAD` contains the gated diff. `loop-deliver` says "commit before deliver", but nothing enforces it, so the receipt binds a `HEAD` that does not contain the change.

**Change:**
1. In `checkCleanState`, compare the gated `diff.patch` with `git diff <startedRevision>..HEAD` (excluding `.ai-engineering-loop/`). The work counts as committed when `HEAD` contains the change and the working tree has no tracked edits to files in the diff.
2. ASSISTED: block, with `{ why, fix }`. The fix is `git add <files> && git commit`, then rerun `deliver`. UNATTENDED: already blocks on strays; add this check.
3. The receipt says `head == base` loudly if it is ever produced.

**AC:**
- The `happy` sandbox scenario without the commit gets a refusal that names the uncommitted files. With the commit, it delivers.
- `deliver-uncommitted` flips to FIXED.
- A unit test: the gated diff is in the working tree only → error; committed → pass.

**Effort:** S.

## C-48 · P1 · git preflight with one clear message

**Now:** `run` starts a Run that cannot pass Stage 4. The failures that follow are raw `git`/Node errors.

**Change:**
1. One `gitReadiness(rootDir)` check: `git` on PATH, inside a work tree, at least one commit, and (as a warning) identity set.
2. `run`, `quick start` and `run --worktree` refuse before creating a Run, with `{ why, fix }` naming the exact command (`apt/brew install git`, `git init && git add -A && git commit -m init`). `init` and `status` show the same result as a line rather than claiming `Git HEAD ... match`.
3. Wrap the `git` calls in `gate maker --from-git` and the worktree code so a failure becomes a gateError with the same fix, never `spawnSync git ENOENT` or git's usage text.
4. Fix the `Context Baseline Git: untracke` truncation (show `untracked` or `none`).
5. `impact confirm` refuses an empty map outside git (or says why it is empty).

**AC:**
- The `no-git`, `non-git-folder` and `no-commit` scenarios stop at `run` with exit != 0 and a FIX line. None of them shows a git usage dump.
- The 8 probes listed in row 2 flip to FIXED.

**Effort:** M.

## C-49 · P1 · Newcomers get the agent skill on the first try

**Now:** Get Started shows `npx ai-engineering-loop init`, then "tell your coding agent". The skill is never installed on that path. Host status wording hides the gap.

**Change:**
1. README Get Started: three lines. `npm i -g ai-engineering-loop`, `ael setup`, `ael init`. Then the agent prompt. (The command is currently only in the banner image's alt text: "Run the command above".)
2. `init` ends with one line when no host has the skill: `Next: ael setup (installs the ael skill into <detected hosts>)`, or `no agent host found; see README#bring-your-own-ai-agent`.
3. `status` host line has three states: `NOT INSTALLED` (no managed files), `STALE (n behind)`, `CURRENT`. It never says `CURRENT (0 managed)`.
4. `run` prints `AI Agent Ready` only when some host has the skill. Otherwise it prints the `setup` hint.

**AC:**
- `host-stale` scenario: `status` says NOT INSTALLED before `sync-hosts` and CURRENT after.
- `happy`: `status` and `run` say no host has the skill.
- The four probes in row 3 flip to FIXED.

**Effort:** S.

## C-51 · P2 · `doctor` is about the user's machine

**Now:** `doctor` is the release gate (`npm run doctor`). It shows a newcomer 12 green package checks and nothing about their environment.

**Change:**
1. `doctor` (user) checks Node, git, the repo has a commit, git identity, agent host skill state, and the adapter CLI and its auth. Every `!` or `✗` line carries a FIX command (`gh auth login`, `ael setup`, `git config --global user.email ...`).
2. Package checks move to `doctor --package`. The `npm run doctor` / prepublish script switches to it.
3. Exit code: 0 READY, 1 NOT READY (errors), 0 with `READY (warnings)` for warnings only.

**AC:**
- `gh-missing`: the doctor line includes `gh auth login` or the install URL.
- `no-identity`: doctor warns.
- `npm run doctor` still gates the release on the same package checks.
- The four probes in row 5 flip to FIXED.
